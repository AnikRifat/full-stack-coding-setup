# Output and context economy

Ponytail governs the size of the change. This governs the size of everything read, kept, and said around it. Applies to every skill.

## Reading in

Read the narrowest thing that answers the question. Search before opening, open a range before a whole file, and open a whole file only when the change actually spans it. Do not re-read a file already read this session to confirm an edit landed — the edit tool fails loudly.

Inspect once. A fact established during discovery is carried forward to every later step and delegation, not rediscovered at each transition.

Tool output is context. Prefer a command that returns the answer over one that returns a corpus: a count, a filtered match, a single field. Do not print a file to the transcript when the next action is to edit it.

## Keeping

Carry forward decisions, open questions, and artifacts — not the raw material they came from. A resolved question becomes one line of context, not a replayed investigation.

Append a durable record to the file that owns it rather than restating it in the answer.

## Saying out

Lead with the answer, the diff, or the finding. Context and alternatives follow only when they change what happens next.

Each skill names the fields its report must contain. Those fields are the whole report. Do not add a preamble, a restatement of the request, a narration of steps taken, or a summary of a summary.

Use a table for anything enumerable — findings, routes, checks, trade-offs. Use prose for reasoning that a table would distort.

Quote real output for evidence. Paste the failing line, not a paraphrase of it, and only the part that carries the signal.

If the explanation is longer than the thing it explains, cut the explanation.

## Never compress away

Evidence for a claimed cause. The limits of what was verified, and which paths were not. A flagged change to authorization, money, or personal data. Anything explicitly requested, including a report or walkthrough asked for in full. The client-facing half of a support answer, which is written for clarity, not brevity.

Brevity is never a reason to imply a check ran that did not.
