# Audit

Use for “review,” “what is wrong,” “confusing,” “drop-off,” or an unproven quality complaint. Do not change code before synthesis unless a critical safety failure has a bounded repair.

1. Resolve context and primary job; inspect the actual surfaces and project conventions.
2. Walk the task state matrix and collect route/file/screenshot/copy/data evidence.
3. Classify each supported issue, write the principle → user cost → business cost chain, and set severity.
4. Drop unsupported claims into hypotheses; deduplicate findings and apply the redesign scope test.
5. Choose Delete → Default → Defer → Reframe → Add, state effort/risk and a regression check.
6. Produce the audit report with Now/Next/Later, not changing and why, and blocking questions with defaults.

The output is a reviewable report, not a redesign or implementation promise.
