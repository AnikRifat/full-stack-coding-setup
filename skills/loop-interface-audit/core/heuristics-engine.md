# Evidence-to-fix engine

Use **observe → evidence → diagnose → severity → fix → sequence → verify**. Walk a task, never only a page: happy, empty, loading, slow, partial, validation error, server error, permission denied, concurrent edit, duplicate submit, long values, 360px, and keyboard-only.

Write each diagnosis as **principle violated → user cost → business cost**. Unsupported observations belong under hypotheses to validate.

Severity is impact × frequency × reversibility. Money, personal data, health, irreversible operations, authorization, and permission leaks are never below High. Prefer fixes in this order: **delete → default → defer → reframe → add**. State surface, effort (`S`, `M`, `L`), risk, and a regression check.

Sequence by impact over effort and dependencies into Now, Next, Later, plus an explicit “not fixing, because” list. Resolve conflicts by risk, primary-job success, expert efficiency, novice support, then aesthetics.
