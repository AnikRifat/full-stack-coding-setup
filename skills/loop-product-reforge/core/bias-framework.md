# B.I.A.S. Diagnosis

Diagnose what is wrong by understanding how people think, identifying friction, and spotting problems in the product or user journey.

**B — Behavior**
What is the user actually trying to do? The underlying goal, not the click.

**I — Intent**
What does the user expect at each step? The mental model of what happens next.

**A — Assumptions**
What are we assuming about the user? Technical literacy, time available, motivation, device, network speed.

**S — Signals**
What evidence shows confusion, friction, or failure? Drop-offs, support tickets, validation errors, duplicate submits, hesitation.

## Output

Produce a list of problems, gaps, friction points, and journey improvements. Feed these into the C.L.E.A.R. design framework to formulate fixes.

> **B.I.A.S. asks: "Why is this experience not working?"**
> **C.L.E.A.R. asks: "How do we make it work better?"**
