# Applied product-design principles

Design for serial attention, recognition over recall, scanning, loss aversion, and the peak-end effect. Keep roughly four meaningful chunks visible at once; group related items with proximity and common regions rather than decorative containers.

- Prefer undo to confirmation. Confirm only irreversible actions and name the consequence in the action, for example `Delete 42 orders`.
- Make affordance, mapping, and feedback explicit: direct feedback within 100ms, a clear state change within one second, and progress UI beyond one second.
- Any decision the system can make with more than 80% confidence should be a default, not a question.
- Labels use user vocabulary; buttons use verb plus object; errors say what happened, why, and one recovery action; numbers include unit and locale.
- Use 150–250ms state changes and 250–400ms spatial transitions. Honor reduced motion and never loop motion without information value.

Apply the **C.L.E.A.R. screen test**: Clarity in three seconds; Load of decisions, fields, and jargon; Evidence that the UI proves its state; one obvious Action; and Recovery for empty, slow, failed, forbidden, and duplicate states. A C.L.E.A.R. failure is at least High severity.
